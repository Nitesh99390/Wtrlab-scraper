# WTR-Lab Telegram Bot

A standalone, production-ready **Telegram bot + Express API** that downloads novels from
[wtr-lab.com](https://wtr-lab.com) as **EPUB / TXT** with the hardened **zero-drop / zero-duplicate**
chapter pipeline (canonical-slug resolver, SSR `__NEXT_DATA__` probe, dialogue-safe boundary parser,
4-pass deep rescue and a post-build verification gate that **blocks delivery** if any chapter is missing or duplicated).

## Features

- `/start`, `/help`, `/wtr`, `/wtrlab` (trending, search by name / ID / URL), `/format`, `/status`, `/cancel`
- Inline buttons: Demo (1-25), Custom range, All chapters, EN/HI edition, Web / Web+ / AI engine
- Paste any `wtr-lab.com` novel link to get a download card
- Express API (`/api/wtrlab/*`) from `wtrlab_catalog_and_routes.ts` + `GET /health`
- Long polling **or** webhook, retry/backoff on network errors, graceful `SIGTERM`/`SIGINT` shutdown
- Never crashes on network hiccups (global handlers, per-update isolation, Telegram 429 / 409 handling)

## Quick start (local)

```bash
git clone https://github.com/Nitesh99390/Wtrlab-scraper.git && cd Wtrlab-scraper
cp .env.example .env          # set BOT_TOKEN (from @BotFather)
npm install && npm run build && npm start
```

Open `http://localhost:3000/health`, then message your bot `/start`.

## Deploy on Render.com (1 step)

1. Render Dashboard -> **New -> Blueprint** -> pick this repo -> paste your `BOT_TOKEN` -> **Apply**.

`render.yaml` does the rest: builds, starts, health-checks `/health`, registers the Telegram **webhook** on the
service's own `RENDER_EXTERNAL_URL`, and generates an `API_AUTH_TOKEN` protecting `/api/*`.

Notes:
- Free web services sleep after ~15 min idle; the first message wakes them (webhook delivers it). While a download is running the bot pings itself so it is not put to sleep mid-job.
- Free instances have an ephemeral disk: catalog cache / chat preferences reset on redeploy. Use a paid plan + disk and set `DATA_DIR` to the mount path to persist them.
- Manual setup instead of a Blueprint: **New -> Web Service**, build `npm ci --include=dev && npm run build`, start `npm start`, health check path `/health`, env `BOT_TOKEN` and `USE_WEBHOOK=true`.

## Deploy on a VPS (1 step)

Needs Node.js >= 20.10 (22 recommended). Then run:

```bash
git clone https://github.com/Nitesh99390/Wtrlab-scraper.git && cd Wtrlab-scraper && cp .env.example .env && nano .env && npm ci --include=dev && npm run build && npx pm2 start dist/index.js --name wtrlab-bot && npx pm2 save
```

(Set `BOT_TOKEN` in `.env`. Long polling is the default, so no domain / HTTPS is needed. Run `npx pm2 startup` once to survive reboots; `npx pm2 logs wtrlab-bot` for logs.)

<details><summary>systemd alternative</summary>

```ini
# /etc/systemd/system/wtrlab-bot.service
[Unit]
Description=WTR-Lab Telegram Bot
After=network-online.target
[Service]
WorkingDirectory=/opt/Wtrlab-scraper
EnvironmentFile=/opt/Wtrlab-scraper/.env

Restart=always
RestartSec=5
TimeoutStopSec=40
User=wtrlab
[Install]
WantedBy=multi-user.target
```
</details>

Use only **one** running instance per `BOT_TOKEN` (two pollers cause Telegram `409 Conflict`).

## Configuration

See [`.env.example`](.env.example). Only `BOT_TOKEN` is required.

| Variable | Purpose |
| --- | --- |
| `BOT_TOKEN` | **Required.** Token from @BotFather |
| `PORT` | HTTP port (default `3000`; Render sets it) |
| `USE_WEBHOOK`, `PUBLIC_URL` | Webhook mode (`PUBLIC_URL` defaults to `RENDER_EXTERNAL_URL`) |
| `API_AUTH_TOKEN` | If set, `/api/*` needs `Authorization: Bearer <token>` |
| `ALLOWED_CHAT_IDS` | Comma-separated chat allow-list |
| `JINA_API_KEY` | Optional r.jina.ai key (higher rate limits) |
| `GEMINI_API_KEY` | Optional, better Hindi translation (Google Translate otherwise) |
| `DATA_DIR` | Cache / preferences directory |
| `MAX_CONCURRENT_JOBS`, `MAX_JOBS_PER_CHAT` | Download concurrency limits |

## Architecture

```
backend/
  wtrlab_live_extractor.ts        } hardened core - UNMODIFIED
  wtrlab_catalog_and_routes.ts    } (code sections, embedded verbatim at build time)
  wtrlab_build_gate.ts            }
  wtrlab_telegram_handlers.ts     }
  index.ts          entry point: dotenv, Express, /health, polling/webhook, graceful shutdown
  bot.ts            command + callback dispatcher
  jobs.ts           download queue, upload retry, shutdown drain
  telegram.ts       Bot API client (retry/backoff, HTML-fallback, file upload)
  hostbase.ts, util.ts, config.ts, logger.ts, registry.ts, prefs.ts, ui.ts, types.ts
  translate.ts, exporters.ts     Hindi translation, EPUB/TXT builders
  generated/wtrlab_core.ts       auto-generated by scripts/assemble.mjs (git-ignored)
scripts/assemble.mjs             wraps the four core files into one typed module (build step)
test/live_wtrlab_verify.ts       live end-to-end zero-drop / zero-duplicate suite (`npm test`)
frontend/WtrlabBrowser.tsx       optional React browser UI (not used by the bot)
```

The four core files are fragments of a larger host app, so `npm run build` first runs `scripts/assemble.mjs`,
which embeds them **byte-for-byte** into `backend/generated/wtrlab_core.ts` (the same technique `test/live_wtrlab_verify.ts` uses), then runs `tsc`.
Editing the core files and rebuilding is all that is needed - nothing is copied by hand.

## API

`GET /health` (public) - status, uptime, bot username, transport, job counts. Scraper routes under `/api/wtrlab/*`:
`rails`, `feed`, `novel/:id`, `chapter`, `verify-chapter`, `verify-all/*`, `cover`, `crawler/*`, `schedule*`.
